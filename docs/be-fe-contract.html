4. Domain DTO (field FE expect)

Department

{ id, code, name }

User (login / AuthContext)

{ id, email, fullName, role: "ADMIN" | "USER", department?: Department | null }

BackendAdminUser / AccountProfile

{ id, login, email, fullName?, activated, authorities?: string[], department?: Department | null }

Room (BackendRoom → FE Room)

{ id, name, capacity, isActive? | active?, lockedDepartment?: Department | null, pricePerHour? }
// visibility BE enforce: public OR locked đúng department user

Booking (flat và/hoặc nested)

{
  id, title, startTime, endTime, status,
  roomId?, userId?, roomName?, userLogin?, userEmail?, userFullName?,
  pricePerHour?, amount?,
  room?: { id, name?, pricePerHour? },
  user?: { id, login?, email? }
}
// amount = snapshot pricePerHour × duration lúc book

DepartmentChangeRequest

{ id, userId, userEmail, userFullName, currentDepartment?, requestedDepartment,
  status, reviewedByLogin?, reviewedDate?, createdDate? }

Notification

{ id, type, title, message, bookingId?, readDate?, createdDate?, read? }
// read = read ?? Boolean(readDate)

RevenueReport

{
  yearMonth, totalAmount, totalBookings, averageAmount, cancelledCount, cancellationRate,
  previous: { /* same period fields */ },
  byRoom: [{ roomId, roomName, bookingCount, amount, sharePercent? }],
  byDay: [{ date, bookingCount, amount }]
}
// số có thể number | string — FE Number(...)

7. Quy tắc nghiệp vụ BE phải giữ

  • Room visibility: public hoặc locked đúng department user (không chỉ filter FE).
  • USER book → PENDING; ADMIN approve/reject; EXPIRED do BE khi PENDING quá startTime.
  • Profile: fullName/email update ngay; đổi department qua request + admin duyệt.
  • amount snapshot trên booking; invoices = booking đã duyệt có amount.
  • Admin path ưu tiên /admin/…; FE có fallback path không-admin nếu 404.
  • Create booking: FE gửi roomId + room: { id } — không gửi userId (BE lấy từ JWT).
