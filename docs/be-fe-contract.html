7. Quy tắc nghiệp vụ BE phải giữ

  • Room visibility: public hoặc locked đúng department user (không chỉ filter FE).
  • USER book → PENDING; ADMIN approve/reject/cancel; EXPIRED do BE khi PENDING quá startTime.
  • Admin bookings UI: 3 tabs — pending / upcoming (upcoming=true) / all (Lịch sử). Badge: page=0&size=1 → totalElements.
  • Profile: fullName/email update ngay; đổi department qua request + admin duyệt.
  • amount snapshot trên booking; invoices = booking đã duyệt có amount.
  • Admin path ưu tiên /admin/… — BE map cả /api/admin/rooms và /api/admin/bookings. FE fallback path không-admin chỉ khi HTTP 404 (legacy).
  • Approve/reject/cancel booking và approve/reject dept-change: sau khi đổi status, BE xóa notif PENDING liên quan. @Modifying delete notif phải flushAutomatically = true (cùng clearAutomatically) — nếu chỉ clear PC mà chưa flush, API vẫn 200 + body status mới nhưng DB không đổi → list/badge không giảm.
  • Create booking: FE gửi roomId + room: { id }, times = toISOString() UTC — không gửi userId (BE lấy từ JWT).
